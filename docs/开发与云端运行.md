## 数据布局与划分

四库配置在`configs/datasets.json`。环境变量`FIRE_DATASETS_ROOT`或CLI的`--datasets-root`只改变共享数据根，保持各数据的版本子目录。

| 数据 | 预期原标签布局 | 预期图像布局（完整包恢复后可配置） | 用途 |
| --- | --- | --- | --- |
| D-Fire | `dfire/kaggle-21527-sha65d81b60/extracted/data/{train,val,test}/labels/*.txt` | 同split下`images/` | 保留Kaggle包train/test，val哈希分dev/cal |
| Home-fire | `home-fire/v1/annotations/{train,val,test}/labels/*.txt` | `home-fire/v1/extracted/{train,val,test}/images/` | 原train/test不动，原val哈希等分dev/cal |
| FASDD_CV | `fasdd-cv/v9/annotations/{train,val,test}.json` | `fasdd-cv/v9/extracted/images/<file_name>` | 原train/test不动，原val等分 |
| FASDD_UAV | `fasdd-uav/v9/annotations/{train,val,test}.json` | `fasdd-uav/v9/extracted/images/<file_name>` | 全部external，保留官方split字段 |

使用原方案salt `fire-master-v1-20261022`和dataset键。D-Fire/Home-fire/CV会与现有冻结逐图清单核对；不按框质量重新切分、不去重。D-Fire原ID 0=smoke、1=fire只在读取视图中映射，统一输出fire=0、smoke=1。

原GT只读：COCO中的ID=0、轻微越界、零面积及原bbox保留在manifest。派生YOLO训练标签仅做格式/类别映射，不裁框或修补标签；原始COCO仍供正式评价。训练器自己的增广/筛框行为需在云端原版检查时记录，不能把格式视图声称为原标注纠错。

### 完整数据准备：优先在低价云服务器执行

```bash
# 在云端项目根，先正确设置共享数据根。此命令不训练模型。
export FIRE_DATASETS_ROOT=/root/rivermind-data/shared/datasets
python3 -B code/fire_r2_cli.py prepare --dataset homefire --output artifacts/data/homefire-v1
```

`prepare`先检查全部文件存在和发布数量，再逐图解码（Pillow）、核COCO尺寸，生成本项目独立的图像软链接、派生labels、带原框的manifest和fit/dev/cal/test清单。只在全部成功后原子提交；失败清除本次临时目录，原数据不动。不覆盖已有视图。这个操作会产生标签/清单并解码全库，应在CPU准备阶段安排，不能把它当本机必跑轻量检查。

`train.yaml`只引用fit和dev，cal/test不参与训练选择；UAV的external视图不会生成训练yaml。软链接训练视图应在云端重建，不上传本机绝对软链接作为可用云数据。配置SHA和源标签digest写入`view.json`。

## 上传：先看计划，再明确执行

```bash
# 本机：只打包小型代码，不含环境、数据、权重、缓存或*.local.*配置。

# SSH别名和staging同意配置好后；不带--execute只显示命令。
python -B code/fire_r2_cli.py upload --cloud-config configs/cloud.local.json --kind code --source artifacts/staging/fire-r2-code.zip --remote-relative fire-r2-code.zip

```

上传支持单个现有文件：code限定为`artifacts/staging`下代码包；data从datasets入口读取，允许引用项目内已有原包软链接。`--kind data --remote-relative <dataset>/<version>/raw/<file>`上传到共享数据根。SSH固定校验主机密钥，不关闭安全校验；远端需要python3、rsync和sha256sum。首次SSH主机信任需用户通过可靠信息确认，失败时不会绕过。

远端数据按同一dataset/version的`shared-datasets/.locks/<dataset>__<version>.lock/`目录锁串行写入，代码包按目标文件目录锁串行写入；已有文件若SHA相同直接复用，不同则拒绝覆盖，换版本目录。传输完成核对SHA-256，回执保存于`artifacts/transfers`；不自动删除本地原包。上传/校验失败保留本地与远端partial并记录。旧的mkdir锁与GPU fcntl锁用途不同，不混用。

代码包在云端`incoming/`收到后，用户/助手先核验，再解压到本研究目录。包中仅包含由bundle白名单打包的本项目代码和文档；`configs/cloud.local.json`不在包中，应在具体服务器上根据实际授权配置。
