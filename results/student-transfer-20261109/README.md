# 正向收益优先：学生三组对照准备与执行队列

本阶段完成总方案更新、联合软监督实现、真实教师CPU评分先导、学生网络前向/反向检查，以及后续GPU/CPU队列接续。正式学生效果待三组完整100轮结果；当前先导是工程验证，不能当作学生AP提升。

## 三组公平对照

三组均为同一YOLO26s初始化、同一训练辅助头、D-Fire完整14122张fit、seed17、640、batch16、AMP、100轮及相同选模/校准规则。

| 组别 | 原GT火/烟存在性 | 联合四态目标 | 代码因子 |
|---|---|---|---|
| P0无教师 | 原硬标签BCE | 原GT one-hot | B+JP |
| T_base基础教师 | 相同原硬标签BCE | 0.75 GT＋0.25基础2B联合概率 | B+TP |
| T_adapted适配教师 | 相同原硬标签BCE | 0.75 GT＋0.25适配2B联合概率 | B+TP |

辅助头前2维用于存在性，后4维用于empty/smoke_only/fire_only/both；三组损失系数同为0.1 BCE＋0.05四态CE，前5轮warmup，既定1/4 clean批次使用辅助监督。原检测框、类别文件、主检测loss与等权数据均保持。部署移除辅助头；没有在线Qwen调用。既有配对B作为无辅助头参考复用。

主要比较P0−B、T_base−P0、T_adapted−P0、T_adapted−T_base，分别判断GT辅助、基础教师、适配教师及适配本身的作用。模型容量和辅助loss预算保持可比。

## 教师分数与实现

冻结同一短场景指令，枚举四种fire/smoke yes/no候选。采用模型合法token的条件概率构建联合分布，真实类别不进入评分函数。每图4候选，GPU batch_images=4对应16个候选序列。四态联合信息完整传给学生，不只保留边缘值。模型版本、adapter SHA、数据清单、提示、评分源码、精度、batch及图像/视图SHA绑定；正式缓存必须覆盖全部fit。

基础教师为Qwen3-VL-2B-Instruct固定revision，适配教师使用同一基座加已完成250更新的LoRA，adapter SHA为aed33157cc068c13e58c9b8e0dd2a34d19667e7d555a62ce32b0c7438b5ee855。缓存全在云端，跨种子可复用。生成完成后复用内部holdout256图的缓存分数计算MAP/NLL/Brier，无需再推理；结果完整保存，不用于调温度或筛掉样本。

借鉴[软目标蒸馏与真实标签共同监督的思路](https://arxiv.org/html/1503.02531v1)，GT主导比例和联合训练头为本轮固定场景适配选择，不声称是原文最优参数。原方案准则、SCI二区目标、三个来源四部分及止损要求保留。
